# must-monitor-bot

Локальный мониторинг и управление гибридными инверторами **MUST PV18 / PV1800** (и совместимыми) через штатный Wi‑Fi‑стик **EyeBond / SmartESS** — без облака, без сторонних сервисов и без перепрошивки.

- 📊 **Веб‑дашборд**: схема потоков энергии, графики мощности и напряжения батареи, детали, журнал. Тёмная тема, адаптирован под телефон.
- 🤖 **Telegram‑бот**: статус, управление кнопками, сводка за сутки и **уведомления**: пропала сеть / сеть вернулась / ошибка инвертора / батарея садится / нет связи.
- ⚙️ **Управление** (по PIN): заряд от сети вкл/выкл, режим работы (UTI/SBU/…), ток заряда, пороги батареи, напряжения absorption/float — только из белого списка, с проверкой диапазонов, чтением значения обратно и журналом изменений.
- 📱 Работает на **старом Android‑телефоне (Termux)**, Mac, Linux, Raspberry Pi или VPS (Docker).
- 🧩 **Без зависимостей**: чистый Node.js 18+.

```
[MUST] ──RS485── [стик EyeBond] ──Wi‑Fi, TCP 8899──▶ [must-monitor-bot] ──▶ браузер / Telegram
```

> ⚠️ Проект не связан с MUST Solar или EyeBond. Протокол и карта регистров получены реверс‑инжинирингом сообществом. Запись настроек в инвертор — на ваш риск.

## Как это работает

Стик EyeBond сам не принимает подключения — он дозванивается до облака SmartESS. Один UDP‑пакет `set>server=<IP>:8899;` на порт 58899 стика заставляет его подключаться к вашему компьютеру. Дальше по этому соединению идёт Modbus RTU до инвертора (slave id 4). Скрипт сам определяет вариант прошивки стика («AT + голый Modbus» или «EyeBond‑заголовок, FC=4»).

Пока стик подключён к must-monitor-bot, приложение SmartESS данных не получает. Вернуть облако — перенастроить сеть стика в приложении SmartESS.

## Быстрый старт (Mac / Linux)

Нужен Node.js 18+. Компьютер и стик — в одной сети.

```bash
git clone https://github.com/InlineDev/must-monitor-bot.git
cd must-monitor-bot
cp .env.example .env && nano .env      # как минимум LOGGER_IP
node dashboard.mjs
```

При запуске в консоли появятся адреса веб‑версии — открывайте любой:

```
дашборд (с паролем):
  ➜ Локально:  http://localhost:3000
  ➜ Сеть:      http://192.168.0.173:3000
```

Адрес «Сеть» открывается с любого устройства в том же Wi‑Fi. IP стика можно найти в списке клиентов роутера (имя обычно похоже на PN с наклейки, `E5000…`). На macOS разрешите входящие подключения для `node`, если система спросит.

## Настройки (`.env`)

Все настройки — в файле `.env` рядом с `dashboard.mjs`; он подхватывается автоматически и не попадает в git. Шаблон — [`.env.example`](.env.example). Флаги командной строки важнее `.env`.

| Переменная | Флаг | По умолчанию | Что делает |
|---|---|---|---|
| `LOGGER_IP` | первый аргумент | — | IP стика EyeBond в домашней сети |
| `WEB_ENABLED` | `--web` / `--no-web` | `true` | Веб‑дашборд. `false` — только опрос и Telegram‑бот |
| `HTTP_PORT` | `--http` | `3000` | Порт веб‑дашборда |
| `HTTP_HOST` | `--http-host` | `0.0.0.0` | `127.0.0.1` — веб только с этого устройства |
| `DASH_USER`, `DASH_PASS` | — | `admin`, пусто | Логин/пароль на веб (Basic Auth) |
| `CONTROL_PIN` | `--control-pin` | пусто | PIN раздела «Управление» в вебе; пусто — только просмотр |
| `TELEGRAM_TOKEN` | `--telegram-token` | пусто | Токен от @BotFather; пусто — бот выключен |
| `TELEGRAM_PASSWORD` | — | пусто | Пароль доступа к боту: ввёл один раз — доступ навсегда |
| `TG_BAT_LOW` | — | авто | Порог уведомления «батарея садится», В |
| `INTERVAL` | `--interval` | `15` | Период опроса, с |
| `SLAVE` | `--slave` | `4` | Modbus slave id инвертора |
| `HOST` | `--host` | авто | IP этого устройства, если определился неверно |
| `ENV_FILE` | — | `./.env` | Путь к другому файлу настроек |

Примеры:
- **только бот** (без сайта): `WEB_ENABLED=false`, `TELEGRAM_TOKEN=…`;
- **бот + сайт в домашней сети**: `WEB_ENABLED=true`, `DASH_PASS=…`, `CONTROL_PIN=…`, `TELEGRAM_TOKEN=…`.

Разовое чтение в консоль без дашборда: `node must-eybond.mjs <IP_стика> [--json] [--debug]`.

## Android‑телефон (Termux) + PM2

Старый телефон на зарядке (лучше — от выхода инвертора, вместе с роутером) — бесплатный круглосуточный сервер.

1. Установите **Termux** и **Termux:Boot** из **F‑Droid** (версии в Google Play устарели). Откройте Termux:Boot один раз.
2. Установка:
   ```bash
   pkg update -y && pkg install -y nodejs git
   npm install -g pm2
   git clone https://github.com/InlineDev/must-monitor-bot.git ~/must-monitor-bot
   cd ~/must-monitor-bot
   cp .env.example .env && nano .env && chmod 600 .env
   ```
3. Запуск:
   ```bash
   pm2 start dashboard.mjs --name must
   pm2 save
   termux-wake-lock
   pm2 logs must --lines 30 --nostream      # адреса веба и статус бота
   ```
4. Автозапуск после перезагрузки телефона:
   ```bash
   mkdir -p ~/.termux/boot
   printf '#!/data/data/com.termux/files/usr/bin/sh\ntermux-wake-lock\npm2 resurrect\n' > ~/.termux/boot/start-must.sh
   chmod +x ~/.termux/boot/start-must.sh
   ```
5. В настройках Android снимите ограничения батареи для Termux.

| Что | Команда |
|---|---|
| Статус / логи | `pm2 status` / `pm2 logs must` |
| Применить изменения `.env` | `pm2 restart must` |
| Обновиться с GitHub | `cd ~/must-monitor-bot && git pull && pm2 restart must` |

Без PM2 можно запустить одной командой `LOGGER_IP=<IP_стика> bash start.sh`: скрипт сам сгенерирует пароль на веб и PIN (`.dashpass`, `.controlpin`), включит бота, если есть файл `.tgtoken`, а с `TUNNEL=1` поднимет временную ссылку `trycloudflare.com` с QR‑кодом (нужны `pkg install cloudflared libqrencode`).

## Telegram‑бот

1. В Telegram: **@BotFather** → `/newbot` → получите токен.
2. В `.env` впишите `TELEGRAM_TOKEN=…` и придумайте пароль `TELEGRAM_PASSWORD=…`.
3. Запустите дашборд, откройте своего бота и отправьте ему пароль.

Кто один раз отправил верный пароль, получает доступ **навсегда** — он запоминается в `data/telegram.json`, после перезапуска ничего вводить не нужно. Сообщение с паролем бот сразу удаляет из переписки. Так же можно дать доступ жене или соседу — просто скажите им пароль. Если пароль поменять в `.env`, все чаты отвяжутся и войти можно будет только с новым паролем. Посторонним без пароля бот ничего не показывает; после 5 неверных попыток чат блокируется на 30 минут.

**Меню:** 📊 Статус · ⚙️ Настройки · 📈 Сутки · 🔔 Уведомления (уведомления включены по умолчанию; кнопка показывает текущее состояние и даёт явно включить или выключить)

**Уведомления:**
- 🔴 пропала сеть (время, напряжение батареи, нагрузка) — подтверждается двумя замерами подряд;
- 🟢 сеть вернулась — и сколько её не было;
- ⚠️ ошибка инвертора (с расшифровкой) и ✅ когда сброшена;
- 🪫 батарея садится без сети (порог = «переход на сеть» + 0,5 В, или `TG_BAT_LOW`);
- ⚠️ нет данных больше 5 минут.

## Сервер в интернете (VPS, Docker)

Стик может подключаться не только к локальной машине, но и к вашему серверу через интернет. Всё нужное для сервера лежит в папке [`server/`](server/) (подробности — в [`server/README.md`](server/README.md)).

```bash
cd server
cp .env.example .env && nano .env      # ALLOW = внешний IP дома, DASH_PASS, CONTROL_PIN, TELEGRAM_TOKEN
docker compose up -d --build
sudo ufw allow from <ВНЕШНИЙ_IP_ДОМА> to any port 8899 proto tcp
```

Затем **один раз из домашней сети** перенаправьте стик на сервер:

```bash
node announce.mjs <IP_стика> <IP_сервера>
```

Протокол стика не шифруется и без пароля — открывайте порт 8899 только для IP дома. Для веб‑доступа поставьте перед дашбордом Caddy/nginx с HTTPS (`HTTP_HOST=127.0.0.1`). Если стик после отключения питания возвращается в облако — повторите `announce.mjs`.

## Управление: что можно менять

| Настройка | Регистр | Примечание |
|---|---|---|
| Заряд от сети вкл/выкл | 20143 | Переключает источник заряда «солнце + сеть» ↔ «только солнце» |
| Источник заряда | 20143 | |
| Ток заряда от сети | 20125 | 10–60 А, шаг 10 (PH18-3024 PRO) |
| Макс. общий ток заряда | 20132 | 1–80 А |
| Режим работы | 20109 | UTI / SBU / SUB / SOL |
| Режим поиска нагрузки | 20104 | |
| Напряжение заряда (absorption) | 10104 | не ниже float |
| Напряжение поддержки (float) | 10103 | не выше absorption |
| Переход на сеть / возврат на батарею | 20118 / 20119 | |
| Отсечка по низкому напряжению | 20127 | |

Диапазоны пересчитываются под номинал батареи (12/24/48 В). Калибровочные регистры (20009–20016) и сбросы счётчиков записать нельзя. Регистр 20106 (InverterChargerFromGridEnable) на PV18 принимает команду, но значение не меняется — поэтому «Заряд от сети» реализован через 20143.

Все изменения пишутся в `data/audit.jsonl` и видны в дашборде.

## Файлы

| Файл | Назначение |
|---|---|
| `dashboard.mjs` | HTTP‑сервер, SSE, история, API управления, запуск бота |
| `dashboard.html` | Веб‑интерфейс |
| `telegram.mjs` | Telegram‑бот (long polling) |
| `must-eybond.mjs` | Связь со стиком EyeBond: перенаправление, сессия, чтение/запись Modbus |
| `must.mjs` | Карта регистров MUST и декодер |
| `controls.mjs` | Белый список настроек и проверки |
| `solarman.mjs` | Клиент Solarman V5 (для стиков Solarman, порт 8899) |
| `announce.mjs` | Перенаправить стик на указанный сервер |
| `start.sh` | Запуск на Android (Termux) одной командой без PM2 |
| `.env.example` | Шаблон настроек |
| `server/` | Версия для VPS: Dockerfile, docker-compose, `.env.example` |

Данные хранятся в `data/` (история за 48 ч, журнал изменений, привязанные чаты Telegram) — папка в `.gitignore`, в репозиторий не попадает.
